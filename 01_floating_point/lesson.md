# 1단원: 오차와 부동소수점

## 1. 컴퓨터는 실수를 "근사"로 저장한다

`float64`(파이썬의 `float`)는 이진수로 `±(1.xxx...) × 2^e` 형태를 저장합니다.
가수부 52비트 → 유효숫자 약 15~16자리.

`0.1`은 이진수로 `0.0001100110011...`처럼 무한히 반복되기 때문에 정확히 저장할 수 없어요.
그래서 `0.1 + 0.2 != 0.3`.

## 2. 핵심 용어

| 용어 | 정의 |
|---|---|
| 절대오차 | `|x - x̂|` |
| 상대오차 | `|x - x̂| / |x|` |
| 반올림 오차 | 유한 자릿수로 저장해서 생기는 오차 |
| 절단 오차 | 무한 과정(급수, 극한)을 유한에서 끊어서 생기는 오차 |
| 기계 엡실론 `ε` | `1 + ε > 1`인 가장 작은 양수. float64에서 약 `2.22e-16` |

수치해석 오차의 대부분은 **반올림 오차 vs 절단 오차의 줄다리기**입니다.
(수치 미분 단원에서 이걸 그래프로 보게 돼요.)

## 3. 조심해야 할 상황: 비슷한 수의 뺄셈 (상쇄)

`1.0000001 - 1.0000000`처럼 거의 같은 두 수를 빼면 앞자리 유효숫자가 다 날아가고
**이미 있던 작은 오차만 남습니다.** 이것을 *catastrophic cancellation*이라고 해요.

해결의 기본 아이디어는 **수식을 수학적으로 같지만 수치적으로 안정한 형태로 바꾸는 것**입니다.

예) `(1 - cos x) / x²` (x가 작을 때) → `2 sin²(x/2) / x²`

## 4. 조건수 (condition number)

문제 자체가 입력의 작은 변화에 얼마나 민감한가를 나타냅니다.
함수 `f`의 조건수:

```
κ(x) ≈ | x f'(x) / f(x) |
```

- 조건수가 크다 = **알고리즘이 아무리 좋아도** 결과가 부정확할 수 있다 (문제가 원래 민감함)
- 알고리즘이 나쁘다 = 문제는 괜찮은데 계산 방식 때문에 오차가 커진다 (불안정)

이 둘을 구분하는 것이 이 단원의 가장 중요한 감각입니다. 3단원(선형 시스템)에서 행렬의 조건수로 다시 만나요.
